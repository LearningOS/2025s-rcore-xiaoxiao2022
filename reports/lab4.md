**ch6**: 在easy-fs文件系统中，root inode（根索引节点）的作用：

1. ‌**核心作用**‌

- 作为文件系统目录树的起点，存储根目录的元数据和数据块指针‌
- 通过root inode可以访问文件系统中的所有其他文件和目录‌
- 在磁盘布局中，root inode通常位于超级块之后，是文件系统初始加载的第一个inode‌

1. ‌**损坏后果**‌

- 文件系统将无法正确挂载，因为无法定位根目录‌
- 所有文件和目录的访问路径都会失效，表现为"文件不存在"错误‌
- 可能导致整个文件系统数据不可访问，需要依赖备份或修复工具‌

1. ‌**技术细节**‌

- root inode损坏会影响DiskInode到内存Inode的映射关系‌
- 由于inode采用链式结构，单个inode损坏可能导致级联错误‌
- 文件系统恢复时通常需要首先修复root inode的指针信息‌

**ch7:**

在 Linux 终端中，`pipe`（管道）的一个典型应用是组合多个命令来完成复杂任务。比如使用 `cat` 和 `wc` 统计文件行数：

```
cat filename.txt | wc -l
```

### 管道的工作原理

1. `|` 创建匿名管道，连接前序（`cat`）和后续（`wc`）进程
2. `cat` 的输出直接作为 `wc` 的输入，无需临时文件
3. 数据通过内核缓冲区流动（默认64KB），实现高效流式处理

### 多进程通信的改进方案

当需要多进程复杂通信时，传统管道（每对进程一个pipe）的替代方案：

‌**1. 命名管道（FIFO）**‌

```
process1 > mypipe & 
process2 < mypipe &
```

优势：解耦进程关系，允许任意进程通过文件系统路径访问

‌**2. 消息队列（推荐方案）**‌

```
int msgid = msgget(IPC_PRIVATE, 0666);
msgsnd(msgid, &message, sizeof(data), 0);
msgrcv(msgid, &buffer, sizeof(data), mtype, 0);
```

优势：

- 支持多对多通信模式
- 消息类型字段实现选择性接收
- 内核持久化避免管道断裂问题

‌**3. UNIX Domain Socket**‌

```
bind(sockfd, (struct sockaddr*)&addr, sizeof(addr));
```

优势：支持双向通信和复杂拓扑结构

### 性能对比

| 机制        | 最大带宽 | 延迟   | 适用场景       |
| ----------- | -------- | ------ | -------------- |
| 匿名管道    | ~1GB/s   | 微秒级 | 线性处理流水线 |
| 命名管道    | ~800MB/s | 微秒级 | 持久化简单通信 |
| 消息队列    | ~500MB/s | 毫秒级 | 结构化数据交换 |
| UNIX Socket | ~3GB/s   | 微秒级 | 复杂进程拓扑   |

根据具体场景选择：流水线处理用管道，结构化通信用消息队列，高性能需求用Socket。
